# ADR-062: alt: identifiers with 20-byte addresses and EIP-55 checksums
Status: Accepted
Date: 2026-10-14
Context: The State asked for account addresses written as `alt:` followed by an Ethereum-style
address, transaction IDs as `alt:T…` and block IDs as `alt:B…`, replacing the `AL:`, `AL:T`
and `AL:B` Bech32m forms of Sections 11-12.1 (62 characters each). Asked to choose, the
project owner picked the true Ethereum length (20-byte addresses, not the 32-byte account hash
in hex) and no `0x` after the prefix.

Protocol version 1 is not frozen: no production network has activated it and
`crates/execution/src/rules/frozen.toml` does not exist (as in ADR-061). The change needs no
new protocol version and no migration. It does change every address, every encoded
transaction and block, and the genesis hash, so existing devnets are started again from
genesis; an old data directory is refused by the genesis check rather than misread.

Decision:
  1. An address is 20 bytes: the last 20 bytes of `account_hash` (Section 11 derivation
     unchanged), the way Ethereum takes the last 20 bytes of its key hash. The 1-byte
     `address_type` leaves the payload; the type codes stay as the first byte hashed, which
     keeps the derivation domains apart. Native modules are 19 zero bytes followed by the
     module id, so "is this a module" is still decidable from the address alone (the bridge
     refuses to pay one).
  2. Key commitment stays 32 bytes. An account's `pubkey_commitment` is the full
     `account_hash` of its keys, compared in full on every transaction after the first. A 20-
     byte address has 80-bit collision resistance; this keeps a key that only collides with
     an existing address's last 20 bytes from spending its funds. A first-transaction race on
     a brand-new collided address remains as theoretical as on Ethereum.
  3. Text: `alt:` + 40 hex digits (44 characters); `alt:T` and `alt:B` + 64 hex digits (69
     characters). Letters carry the checksum by the EIP-55 rule over
     `Keccak-256(tag || lowercase_hex)`, with `tag` = network HRP + (`""`, `t`, `b`) + `:`.
     Folding the network in follows EIP-1191 and keeps `AddrWrongNetwork` / `IdWrongNetwork`
     and the transaction-versus-block separation of the Bech32m forms. An empty tag
     reproduces EIP-55; the EIP-55 vectors run in `crates/core/src/text_id.rs`.
  4. Exactly one spelling is canonical. All-lowercase, all-uppercase and an uppercase prefix
     are `NonCanonical`; a casing valid for another network is `WrongNetwork`; anything else
     is `Malformed`. `0x` stays rejected everywhere (ADR-021), including after `alt:`.
  5. Event topics that name an address carry it as a 32-byte word, left-padded with 12 zero
     bytes (`Address::to_word`), as Ethereum log topics do. VM `address` and `signer` values
     are the 20 raw bytes.
  6. New dependency `sha3` 0.10 (RustCrypto; MIT/Apache-2.0), used only for the checksum. It
     shares `digest` with the `sha2` already in the tree. Bech32m and its `bech32` test
     oracle are removed.

Consequences: Checksum strength drops. Bech32m detected every error of up to four characters;
EIP-55 lets a mistyped address through about 0.0247% of the time (its own figure, for 40
digits; the 64-digit IDs carry more letters and do better), and an address with no hex letters
(about 1 in 10^8) has no checksum at all. Parsers still
refuse, never repair. Addresses are 18 characters shorter and tx and block IDs 7 longer. The
prefix `alt:` is also the spelling of the private validation network's HRP; the HRP is never
displayed, so the two do not meet in text. Wallet URIs become `aletheia:alt:…`. The explorer,
the national website and every document now show `alt:` forms. Devnets restart from genesis;
`genesis/devnet-explorer.toml` is regenerated by `devnet-traffic genesis`.
