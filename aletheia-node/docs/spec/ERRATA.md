# Specification errata and resolutions

Discrepancies found in `MASTER.md` (v4.0) during implementation. Each entry states what the
code does. Entries marked **Open** need a decision from the named seat before anything
depends on them.

| # | Location | Discrepancy | Resolution | Status |
| --- | --- | --- | --- | --- |
| E-1 | Section 4 ADR register vs Sections 65 and "Changes in v4.0" | ADR-029 to ADR-032 mean different things in the two lists. Section 4 has Rust language policy, no public testnet, physical banknotes and rail access through institutions. Section 65 has versioned rules registry, storage schema, canonical payment model and PayNet boundary, continuing to ADR-036. | The v4.0 numbering (Section 65) keeps 029-036. The four Section 4 decisions are renumbered ADR-040 to ADR-043. ADR-037 onward are taken by decisions made during implementation. | Adopted 2026-10-07 on the project lead's instruction to proceed; Protocol seat may still object |
| E-2 | Section 10 table; Section 24.1 WAL header | `protocol_version` is `u32` there, but `u16` in Section 3.2 (`ProtocolVersion(u16)`), in the block and transaction `version` fields, and in the protocol schedule (Section 44.4). | `u16` everywhere a protocol version is encoded (ADR-038). When the WAL is implemented, its header field is `u16` plus two reserved zero bytes, which keeps the 4-byte slot. | Resolved |
| E-3 | Section 5 | Two subsections are numbered 5.2 ("Rust engineering rules" and "Testing and Quality Frameworks"). | Editorial only. Cite them by title. | Resolved |
| E-4 | Section 11 | Multisig derivation `ace(threshold, sorted_pubkeys)` fixes neither the width of `threshold` nor whether each key carries an `alg_id`. | `threshold u8`, then the ACE list of `PublicKeyEntry { alg_id u8, key bytes }`, strictly ascending. Implemented in `crates/crypto/src/address.rs`. | Adopted 2026-10-07 on the project lead's instruction to proceed; Protocol and Security seats may still object |
| E-5 | Section 9 `AceReader::take` | Input that ends early is reported as `DecodeLengthExceeded`, the same code as a length prefix above its maximum. | Kept as specified. The detail string tells the two apart. | Resolved |
| E-6 | Sections 6.6, 11, 13 | Keys and signatures carry an `alg_id`, but no values are assigned. | ADR-039: 0 is invalid, 1 is Ed25519, 2 is BLS12-381 min-pk, 3 is reserved for ML-DSA. | Resolved |
| E-7 | Section 5.5 | The workspace member list names all 24 crates plus `apps/*`. Cargo refuses a workspace whose members do not exist. | Crates join `members` as they are implemented, in Section 62 phase order. | Resolved |
| E-8 | CLAUDE.md directive 5 vs Section 65 | The ADR template is `docs/adr/0000-template.md` in one place and `docs/adr/ADR-000-template.md` in the other. | `docs/adr/ADR-000-template.md`, matching the `ADR-xxx-<slug>.md` naming of Section 4. | Resolved |
| E-9 | Section 6.7 vs Sections 10 and 55 | "`crypto` depends on nothing protocol-specific", yet domain-separated hashing needs `chain_id` and `network_kind`, and Section 55 places Merkle trees in `crypto`. | ADR-037: `core` owns `H_domain` and the tag registry. `crypto` depends on `core` only for errors, strong types and `H_domain`. | Resolved |
| E-10 | Section 13 `Authorization` | The authorization lists signatures but no public keys. A signature cannot be checked statelessly without the key, and the account's first transaction has no stored key to check against. | ADR-044: the authorization carries `scheme`, `threshold`, the strictly sorted `public_keys` and the signatures. Stateless validation verifies signatures against those keys. Stateful validation binds the keys to the sender: by address derivation for a new account, by the stored `pubkey_commitment` afterwards. | Resolved |
| E-11 | Section 19.5 `TimeoutCertificate` | `{round, high_qc_rounds[], aggregate_sig}` cannot be verified: each signer signed a different message, so the verifier must know who signed which. | Add `epoch` and `signers: SignerBitmap`. `high_qc_rounds[k]` belongs to the k-th set bit. Each timeout signs `H_domain("ALETHEIA/TIMEOUT/v1", ace(round, epoch, highest_qc_round))`; the epoch is included for the same reason the vote digest includes it. | Resolved |
| E-12 | Sections 13 and 14.1 | The transfer payload layout is not given, and the body's `tx_type` and the payload's own variant tag would duplicate each other. | `tx_type` is the payload tag, written once in the body. `Transfer = { recipient Address, asset AssetId, amount u128 }`; `BatchTransfer = list<Transfer> (1..=256)`. Recorded in APS-0003. | Resolved |
| E-13 | Section 41A.4 | `--ink-faint` #6E7178 is described as "4.6:1 on --paper"; it measures 4.41:1 on paper and 4.00:1 on vellum, below WCAG AA for the labels and captions it is used for. | #65686F (same hue, darker): 5.04:1 on paper, 4.57:1 on vellum. Checked in CI by `aletheia-explorer/scripts/check-contrast.mjs`. | Resolved |
| E-14 | Section 41A.7 `splitAmount` | For a 0-decimal asset the fraction is "0" instead of "" and the exact value ends in ".". | Fraction and separator are omitted when `decimals` is 0 (`aletheia-explorer/src/lib/format/amount.ts`). | Resolved |
| E-15 | Section 16.1 | The JMT leaf is `H_domain("ALETHEIA/JMT-LEAF/v1", state_key \|\| H(value))` without saying which hash `H` is. | `H(value)` is plain BLAKE3-256 of the value bytes; domain separation comes from the enclosing leaf hash. Empty subtrees hash to 32 zero bytes. A subtree with one key is that key's leaf at the highest position it can occupy. | Resolved |
| E-16 | Section 42.2 | `set_zstd_max_train_bytes(100 << 20)` without a dictionary size: RocksDB refuses to open ("max_dict_bytes should be nonzero if we're using zstd's dictionary generator"). | Add `set_compression_options(-14, 32767, 0, 16 KiB)`: 16 KiB dictionaries, default window and level. | Resolved |
| E-17 | Sections 10, 38 | `receipt_hash = H_domain(..., ace(Receipt))` leaves the tag unnamed; event hashes and the receipt's `write_set_hash` need tags too, and Section 10 requires every hash to be domain-separated. | Registered `ALETHEIA/RECEIPT/v1`, `ALETHEIA/EVENT/v1`, `ALETHEIA/WRITESET/v1` (APS-0001 extension). | Resolved |
| E-18 | Section 24.2 vs 46A.6 | The fsync table puts `FINALIZE_BEGIN` before the archive append; the exemplar code appends to the archive first. | The 24.2 order is implemented (`crates/node/src/ledger.rs`). Recovery covers a crash at either point: an archived block with an open `FINALIZE_BEGIN` is re-executed, an open `FINALIZE_BEGIN` without an archived block is abandoned. | Resolved |
| E-19 | Section 36 | The application handshake is signed with the node identity key but no domain tag is registered for it. | Registered `ALETHEIA/P2P-HANDSHAKE/v1`. The signed message is TLS exported keying material, a role byte and the ACE hello, which binds the hello to one TLS session and one direction. | Resolved |
| E-20 | Sections 14.1, 19.1 | Headers commit to `validator_set_hash`, but neither the hashed encoding nor a domain is defined. | `validator_set_hash = H_domain("ALETHEIA/VALSET/v1", ace(epoch u64, list<{consensus_pubkey [48], node_key [32], voting_power u64}>))`, members in validator-index order. | Resolved |
| E-21 | Section 19.1 | Quorum is given as both `2F + 1` and `N − F`; they differ when `N ≠ 3F + 1` (N = 5: 3 vs 4). | `Q = N − F`. Any two quorums then share at least `N − 2F ≥ F + 1` validators, so at least one honest validator, for every `N`. | Resolved |
| E-22 | Section 19.6 | `seed(epoch)` uses `finalized_hash_at(epoch_start − 1)`, undefined for epoch 0. | Epoch 0 uses `genesis_id`. | Resolved |
| E-23 | Sections 10, 18.5, 18.8 | Redemption co-authorization and reserve attestations are signed, but no domain tags are registered for them, and the redemption co-signature's message is not defined. | Registered `ALETHEIA/REDEEM/v1` and `ALETHEIA/RESERVE-ATTEST/v1`. The agent signs `H_domain("ALETHEIA/REDEEM/v1", ace(sender, nonce, asset, amount, settlement_ref))`; binding sender and nonce ties a co-signature to one transaction, so it cannot be replayed by another holder or reused by the same one. Attestors sign the attestation fields without signatures. | Resolved |
| E-24 | Sections 18.4 (I9), 18.5, 18.8 | Where the monetary authority keys, attestors, redemption agents and reserve policy live is only sketched ("namespace 65 parameters"), and attestation freshness is stated in epochs in I9 but in slots in 18.8. | One `MonetaryPolicy` record at namespace 65 parameter 3, set at genesis (`[monetary]`) and later by governance. Freshness uses `max_attestation_age_slots` for both acceptance and the I9 check at issuance. Accepted attestations are kept as the latest per feed and in a history keyed by `(feed_id, sequence)` in namespace 80. Mint authorizations are consumed by recording their id with the height in namespace 5. | Resolved |
| E-25 | Section 25.3 (Payroll example) | `PayEveryone` declares `sends coins, emits events`, but `Funds.Withdraw` changes `Funds`, a vault held in storage. The compiler's effect rule reports it (A3005). | Withdrawing from or depositing into a stored vault changes storage and must be declared; `examples/arno/payroll.arno` adds `changes storage`. The rule is kept strict so a reader of the effects list always learns that storage changes. | Resolved |
| E-26 | Sections 33, 35 | A land authority's co-signature and governance proposals need signed or hashed messages, but no domain tags or message layouts are defined. | Registered `ALETHEIA/PARCEL-TRANSFER/v1` (the co-signature covers parcel, new controller, sender and nonce, so it authorizes one transfer by one transaction) and `ALETHEIA/GOV-PROPOSAL/v1` (proposal id over proposer, nonce and action). Governance timelocks count governance epochs of `epoch_slots` slots until epoch transitions arrive (ADR-048). | Resolved |
| E-29 | Section 40B.7 (Mandate) | Mandates are bounded by `first_epoch` and `final_epoch` and debited by calendar frequency, but epochs are not calendar periods. | Mandates and payment requests count UTC days of protocol time (`first_day`, `final_day`, `expires_day`); weekly, monthly, quarterly and yearly mean ISO week, calendar month, quarter and year (ADR-050). | Resolved |
| E-28 | Sections 40B.3, 40B.7, 40D.5 | No transactions maintain account numbers or proxy aliases, and the de-duplication key has a one-byte leg number while a batch may carry 1,000 legs. | Types 141 `AanAssign`, 142 `ProxyRegister`, 143 `ProxyRemove` join the APN range. Batch legs each carry their own UETR and use leg 0 (ADR-050). | Resolved |
| E-27 | Section 25 (Arno syntax), ADR-019 | The Pascal-family surface syntax (`begin ... end`, `:=`, `procedure`, `var` sections, `end.`) was replaced at the project owner's request by a syntax shaped like Java and Solidity that keeps English words for operators and checks. | Section 25 now shows the new syntax; `docs/arno/grammar.ebnf` is normative. Semantics, bytecode and the VM are unchanged: the reference contracts and APS-0015 vectors compile to the same code (ADR-049). | Resolved |
